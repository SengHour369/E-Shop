# Product scanner

Two catalog endpoints. The camera decodes the barcode or QR on the device and sends the text. The server looks up `ProductSku` and fills price, promotion, stock, and variant attributes from the database. A scan does not change stock or `ProductSku.price`.

Gateway: `http://localhost:8080`

Catalog: `http://localhost:8082`

The admin page that calls these routes is `/dashboard/scanner`.

Both routes require an enabled access token. Roles that can call them: `USER`, `SALES`, `STAFF`, `MANAGER`, `ADMIN`. The token subject is the actor. `userId`, `role`, `price`, `productId`, and `inventory` in the body are ignored.

Send `Authorization: Bearer <access token>`.

`X-Request-ID` is optional. A safe value is 1 to 128 characters from `A-Z`, `a-z`, `0-9`, `.`, `_`, `:`, and `-`. Any other value is replaced with `req_` plus a UUID. The same id is returned in the `X-Request-ID` response header and in `requestId`.

`timestamp` is the catalog server local time, with no timezone.

## Store a barcode before scanning

The retail barcode is optional and separate from the internal SKU. Create and update still use the existing product routes. Put `barcode` on each object in the `skus` form field.

`POST /api/v1/products/create/`

`PUT /api/v1/products/update/`

`Content-Type: multipart/form-data`

`skus` is a JSON array. One object:

```json
{
  "description": "Black / 42",
  "barcode": "8850123456787",
  "price": 120.00,
  "quantity": 16,
  "low_stock_threshold": 5,
  "is_default": true
}
```

| Field | JSON name | Rule |
| --- | --- | --- |
| Retail barcode | `barcode` | Optional. Letters and digits are stored in upper case, with spaces removed. Maximum 64 characters. Allowed characters are `0-9`, `A-Z`, `.`, `$`, `/`, `+`, `%`, `-`. |
| Internal SKU | `sku` | Generated by the existing SKU generator. Do not send the barcode in place of the SKU. |
| Update behavior | `barcode` | Omitted: the stored barcode stays. `""`: the stored barcode is cleared. |

`8850123456787` is a valid EAN-13. `8850123456789` fails the check digit and will not match an EAN-13 scan.

A duplicate barcode, a value longer than 64 characters, or a character outside that set fails the product save with HTTP 400:

```json
{
  "requestId": "req_barcode_taken",
  "success": false,
  "message": "Barcode is already assigned to another SKU",
  "status": 400,
  "timestamp": "2026-10-04T00:40:00.000000",
  "data": null
}
```

The other two messages on that same body are `Barcode is too long` and `Barcode contains unsupported characters`.

## POST /api/v1/product-scanner/scan

`Content-Type: application/json`

The client sends the decoded text and, when the detector knows it, the symbology.

```json
{
  "code": "8850123456787",
  "format": "EAN_13"
}
```

| Field | Required | Rule |
| --- | --- | --- |
| `code` | Yes | 1 to 512 characters. The server trims it and removes spaces. |
| `format` | No | One of `EAN_13`, `EAN_8`, `UPC_A`, `UPC_E`, `CODE_128`, `CODE_39`, `QR_CODE`, `SKU`. `ean-13`, `ean_13`, and `EAN 13` are accepted. Omitted: 13 digits are EAN-13, 12 digits are UPC-A, 8 digits are EAN-8, a value with a letter or `-` is SKU, and any other digit string is CODE 128. |

Retail formats must be digits and must pass the GTIN check digit. `-` inside the digits is removed before that check. UPC-A `036000291452` also matches a stored EAN-13 `0036000291452`. UPC-E `04252614` is expanded to UPC-A `042100005264` and EAN-13 `0042100005264`.

`CODE_39`, `CODE_128`, `SKU`, and `QR_CODE` search the barcode column and, when the value is not a GTIN, the internal SKU. A QR URL uses the path segments and query values. Example: `https://shop.example/p/NIKE-BLK-42` looks up `NIKE-BLK-42`.

The same account, format, and normalized code within 1.5 seconds returns the first result again. That repeat still gets the current `requestId`. It does not run another database lookup and it does not count against the limit below.

Each account may run 30 scans in 10 seconds on one catalog instance. The 1.5 second repeat does not count. A different code does.

### Response 200, product found, promotion applied

HTTP 200. `data.originalPrice` is `ProductSku.price`. `data.finalPrice` is the current promotion price. The stored SKU price is not changed.

`availableQuantity` is `quantity - reservedQuantity`, and it is never below 0. `inStock` is true when `availableQuantity` is greater than 0. `lowStock` is true when the SKU is in stock and `availableQuantity` is less than or equal to the SKU low-stock threshold. The default threshold is 5.

`variant` uses the SKU's real attribute names. Color and size are examples, not fixed fields.

`warehouseLocation` is present for `ADMIN`, `MANAGER`, and `STAFF` when inventory has a location. It is omitted for `USER` and `SALES`.

```json
{
  "requestId": "req_scan_42",
  "success": true,
  "message": "Product found",
  "status": 200,
  "timestamp": "2026-10-04T00:41:00.000000",
  "data": {
    "found": true,
    "code": "8850123456787",
    "format": "EAN_13",
    "matchType": "EAN_13",
    "message": "Product found",
    "requestId": "req_scan_42",
    "productId": 100,
    "productSkuId": 501,
    "sku": "NIKE-BLK-42",
    "barcode": "8850123456787",
    "name": "Nike Air Max",
    "originalPrice": 120.00,
    "finalPrice": 96.00,
    "hasPromotion": true,
    "discountPercentage": 20.00,
    "quantity": 16,
    "reservedQuantity": 2,
    "availableQuantity": 14,
    "inStock": true,
    "lowStock": false,
    "active": true,
    "availableForSale": true,

      { "name": "Color", "value": "Black" },

```

### Response 200, product not found

HTTP 200. This is a miss, not an HTTP 404. Null product fields are omitted.

```json
{
  "requestId": "req_scan_46",
  "success": true,
  "message": "Product not found",
  "status": 200,
  "timestamp": "2026-10-04T00:41:40.000000",
  "data": {
    "found": false,
    "code": "96385074",
    "format": "EAN_8",
    "message": "Product not found",
    "requestId": "req_scan_46"
  }
}
```

QR and SKU misses use the same body. `format` is the format after normalization, and `code` is the normalized value.

### Response 400, body cannot be read or a field fails validation

Used when the body is not JSON, `code` is missing or blank, `code` is longer than 512 characters, or `format` is not a supported name such as `PDF417`.

```json
{
  "requestId": "req_scan_400",
  "success": false,
  "message": "Invalid request: check required fields, values and formats",
  "status": 400,
  "timestamp": "2026-10-04T00:42:00.000000",
  "data": null
}
```

Request examples that return that body:

```json
{}
```

```json
{ "code": "", "format": "EAN_13" }
```

```json
{ "code": "123", "format": "PDF417" }
```

### Response 400, the code is the wrong shape

The body parsed, and the scanner rejected the value. `message` is one of the sentences below. The rest of the JSON stays the same.

```json
{
  "requestId": "req_scan_401",
  "success": false,
  "message": "Barcode check digit is invalid",
  "status": 400,
  "timestamp": "2026-10-04T00:42:10.000000",
  "data": null
}
```

| Request `code` | Request `format` | `message` |
| --- | --- | --- |
| `8850123456789` | `EAN_13` | `Barcode check digit is invalid` |
| `12345` | `EAN_13` | `EAN-13 must be 13 digits` |
| `885012345678A` | `EAN_13` | `EAN-13 must contain only digits` |
| `1234567` | `EAN_8` | `EAN-8 must be 8 digits` |
| `9638507A` | `EAN_8` | `EAN-8 must contain only digits` |
| `03600029145` | `UPC_A` | `UPC-A must be 12 digits` |
| `03600029145A` | `UPC_A` | `UPC-A must contain only digits` |
| `0425261` | `UPC_E` | `UPC-E must be 8 digits` |
| `0425261A` | `UPC_E` | `UPC-E must contain only digits` |
| `NIKE_BLK` | `SKU` | `Scanner code contains unsupported characters` |
| 65 or more stored characters | `SKU`, `CODE_128`, or `CODE_39` | `Scanner code is too long` |
| `https://shop.example/not a code` | `QR_CODE` | `QR code did not contain a supported product code` |
| A QR whose only digits fail the check digit | `QR_CODE` | `Barcode check digit is invalid` |

### Response 401, through the gateway

`/api/v1/product-scanner/**` is not a public gateway path. The gateway answers before catalog.

No `Authorization` header and no `eshop_access` cookie:

```json
{
  "requestId": "req_scan_denied",
  "status": 401,
  "error": "UNAUTHORIZED",
  "message": "Missing or invalid Authorization header"
}
```

Expired token, refresh token, disabled account, or a token signed with the wrong secret:

```json
{
  "requestId": "req_scan_denied",
  "status": 401,
  "error": "UNAUTHORIZED",
  "message": "Invalid or expired access token"
}
```

A `POST` that authenticates with the `eshop_access` cookie and sends no `Origin`, or an origin outside the gateway allow list, is HTTP 403 with an empty body.

### Response 401, direct to catalog

`http://localhost:8082` uses the catalog security handler. The header `X-Request-ID` is still set.

```json
{
  "requestId": "req_scan_denied",
  "success": false,
  "message": "Unauthorized",
  "status": 401,
  "timestamp": "2026-10-04T00:42:20.000000",
  "data": null
}
```

### Response 429, catalog scan limit

Header `Retry-After: 1`. This is the catalog limit of 30 lookups in 10 seconds for one account on one instance. A repeated code inside 1.5 seconds does not produce this response.

```json
{
  "requestId": "req_limited",
  "success": false,
  "message": "Too many scan requests",
  "status": 429,
  "timestamp": "2026-10-04T00:42:30.000000",
  "data": null
}
```

If a gateway rate-limit policy is stored for this path, the gateway can return HTTP 429 first, with header `Retry-After: 1` and an empty body. With no policy, the gateway allows the request through.

### Response 500

An unexpected catalog failure:

```json
{
  "requestId": "req_scan_500",
  "success": false,
  "message": "Internal server error",
  "status": 500,
  "timestamp": "2026-10-04T00:42:40.000000",
  "data": null
}
```

## POST /api/v1/product-scanner/recognize

Optional fallback after the camera finds no barcode. Send one still image. Do not call this when a barcode already identified the product. Do not upload the video stream.

`Content-Type: multipart/form-data`

| Part | Required | Rule |
| --- | --- | --- |
| `image` | Yes | One JPEG, PNG, or WebP file. Maximum 1,500,000 bytes. The content type and the file bytes must agree. |

Headers are the same `Authorization` and optional `X-Request-ID` as the scan route.

Catalog checks the file, then sends it to ai-inference. The model returns names and confidence only. Catalog searches its own products. A name the model invents is dropped when no catalog product matches. Confidence of at least `0.90` and exactly one catalog product with the same name sets `exact` to true. Every other hit asks the user to choose.

This route has the same 30 requests in 10 seconds limit. It does not use the 1.5 second barcode cache.

### Response 200, one exact catalog match

```json
{
  "requestId": "req_image_1",
  "success": true,
  "message": "Product recognized",
  "status": 200,
  "timestamp": "2026-10-04T00:43:00.000000",
  "data": {
    "matchType": "AI_IMAGE",
    "confidence": 0.94,
    "exact": true,
    "requiresSelection": false,
    "message": "Product recognized",
    "requestId": "req_image_1",
    "candidates": [
      {
        "productId": 100,
        "productSkuId": 501,
        "name": "Nike Air Max",
        "sku": "NIKE-BLK-42",
        "imageUrl": "https://cdn.example/nike-air-max.jpg",
        "confidence": 0.94
      }
    ]
  }
}
```

`exact: true` still means the user should confirm before a stock or cart write. Price and stock in this body are not included. Load them with `POST /api/v1/product-scanner/scan` using `format` `SKU` and `code` set to `candidates[0].sku`.

### Response 200, the user must choose

Used when confidence is below 0.90, more than one catalog product matches, or the model name is only a partial match.

```json
{
  "requestId": "req_image_2",
  "success": true,
  "message": "Select the matching product",
  "status": 200,
  "timestamp": "2026-10-04T00:43:10.000000",
  "data": {
    "matchType": "AI_IMAGE",
    "confidence": 0.74,
    "exact": false,
    "requiresSelection": true,
    "message": "Select the matching product",
    "requestId": "req_image_2",
    "candidates": [
      {
        "productId": 100,
        "productSkuId": 501,
        "name": "Nike Air Max",
        "sku": "NIKE-BLK-42",
        "imageUrl": "https://cdn.example/nike-air-max.jpg",
        "confidence": 0.74
      },
      {
        "productId": 102,
        "productSkuId": 510,
        "name": "Nike Air Max 90",
        "sku": "NIKE-AM90-BLK-42",
        "imageUrl": "https://cdn.example/nike-air-max-90.jpg",
        "confidence": 0.74
      }
    ]
  }
}
```

At most five candidates are returned.

### Response 200, no catalog product

The model answered, and none of the names exist in the catalog. `confidence` is the highest model score. It is omitted when the model returns no names. `candidates` is empty. Invented product ids are not returned.

```json

  "requestId": "req_image_3",
  "success": true,
  "message": "No matching catalog product",
  "status": 200,
  "timestamp": "2026-10-04T00:43:20.000000",
  "data": {
    "matchType": "NO_CATALOG_MATCH",
    "confidence": 0.81,
    "exact": false,
    "requiresSelection": false,
    "message": "No matching catalog product",
    "requestId": "req_image_3",
    "candidates": []
  }
}
```

```json
{
  "requestId": "req_image_4",
  "success": true,
  "message": "Product recognition is unavailable",
  "status": 200,
  "timestamp": "2026-10-04T00:43:30.000000",
  "data": {
    "matchType": "AI_UNAVAILABLE",
    "exact": false,
    "requiresSelection": false,
    "message": "Product recognition is unavailable",
    "requestId": "req_image_4",
    "candidates": []
  }
}
```

### Response 400, image rejected

```json
{
  "requestId": "req_image_400",
  "success": false,
  "message": "Image is required",
  "status": 400,
  "timestamp": "2026-10-04T00:43:40.000000",
  "data": null
}
```

| Condition | `message` |
| --- | --- |
| The `image` part is present and empty | `Image is required` |
| File larger than 1,500,000 bytes | `Image is too large` |
| Content type is not JPEG, PNG, or WebP, or the bytes do not match that type | `Image must be JPEG, PNG, or WebP` |
| The file cannot be read | `Image could not be read` |

A request that omits the `image` part is HTTP 500 with `message` `Internal server error`.

### Response 401 and 429

The gateway 401 bodies, the direct catalog 401 body, and the 429 body are the same JSON shown for `POST /api/v1/product-scanner/scan`. The 429 `message` remains `Too many scan requests`.

## Internal image call

The browser does not call this. Catalog calls it after `POST /api/v1/product-scanner/recognize` accepts the file.

`POST http://ai-inference:8000/api/v1/ai/vision/products`

Local process: `http://localhost:8000/api/v1/ai/vision/products`

This path is not on the gateway. The body has no bearer token, no catalog id, and no price.

```json
{
  "mediaType": "image/jpeg",
  "imageBase64": "/9j/4AAQ..."
}
```

`imageBase64` is standard base64 of the image bytes. Maximum decoded size is 1,500,000 bytes. `mediaType` is `image/jpeg`, `image/png`, or `image/webp`. Extra JSON fields are rejected.

### Response 200

```json
{
  "candidates": [
    { "name": "Nike Air Max", "confidence": 0.94 },
    { "name": "Nike Air Max 90", "confidence": 0.74 }
  ]
}
```

`candidates` has at most five objects. Each object has only `name` and `confidence`. `confidence` is from 0 to 1, rounded to two decimals. An unrecognized photo is an empty list:

```json
{
  "candidates": []
}
```

### Response 422

Invalid media type, invalid base64, or an empty image:

```json
{
  "code": "AI_INVALID_PARAMETERS",
  "message": "The image is invalid.",
  "requestId": "req_image_1"
}
```

A body that fails schema validation, including an extra field, uses the same status and code with `message` `The routing request is invalid.`

### Response 502, 503, and 504

The provider failed, the response could not be read, or the call timed out. `message` does not include the provider payload or the API key.

```json
{
  "code": "AI_PROVIDER_ERROR",
  "message": "AI routing is temporarily unavailable",
  "requestId": "req_image_1"
}
```

| HTTP | `code` |
| --- | --- |
| 502 | `AI_PROVIDER_ERROR` or `AI_INVALID_RESPONSE` |
| 503 | `AI_PROVIDER_ERROR` |
| 504 | `AI_PROVIDER_TIMEOUT` |

Catalog turns every one of these into the recognize response with `matchType` `AI_UNAVAILABLE`.
